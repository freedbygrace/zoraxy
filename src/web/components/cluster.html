Docker Swarm Setup Guide

Finding Your Swarm Service Name

Run this command on a Swarm manager node:

docker service ls

Your service name is in the NAME column. Use tasks.<NAME> for the DNS name to discover all replicas.

Example Stack Configuration

version: '3.8'
services:
  zoraxy:
    image: zoraxy:latest
    deploy:
      replicas: 3
    environment:
      - CLUSTER=true
      - CLUSTER_SECRET=<your-secret>
      - CLUSTER_SWARM=true
      - CLUSTER_SWARM_SERVICE=tasks.zoraxy
      - ZORAXY_ADMIN_USER=admin
      - ZORAXY_ADMIN_PASSWORD=<your-admin-password>
      - ZORAXY_BOOTSTRAP_UI=true
    ports:
      - "80:80"
      - "443:443"
    networks:
      - zoraxy-net
networks:
  zoraxy-net:
    driver: overlay

Note: ZORAXY_BOOTSTRAP_UI=true creates a /admin/ virtual directory on the root endpoint, allowing you to access the management UI at https://<node-ip>/admin/ via the reverse proxy without publishing port 8000.

Generating a Secure Secret

Click the Generate button above, or use one of these commands:

Linux/macOS:

openssl rand -base64 32

PowerShell:

[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
Certificate Synchronization

How Certificate Sync Works

When cluster mode is enabled, certificates are automatically synchronized between nodes:

  • Upload: When you upload a certificate on any node, it is automatically pushed to all peer nodes.
  • ACME/Let's Encrypt: When a certificate is obtained or renewed via ACME, it is automatically distributed to all peers.
  • Conflict Resolution: Timestamp-based conflict resolution ensures the newest certificate always wins.

Alternative: Shared Storage

For Docker Swarm deployments, you can also use shared storage instead of replication:

volumes:
  - type: volume
    source: zoraxy-certs
    target: /opt/zoraxy/config/certs
    volume:
      driver: local
      driver_opts:
        type: nfs
        o: addr=nfs-server,rw
        device: ":/exports/zoraxy-certs"
